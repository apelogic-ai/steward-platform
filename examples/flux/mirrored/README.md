# task-auth install with Flux, from a registry mirror

The [task-auth Flux example](../task-auth/README.md), with every chart, image
and CRD source pulled from the operator's own mirror instead of upstream. The
digests and commits are exactly the BOM's; only the registry, host and leading
path of each reference change. Everything here except this README is
generated by [`scripts/generate.sh`](../../../scripts/generate.sh) from
[`environments/production-mirrored/platform-values.yaml`](../../../environments/production-mirrored/platform-values.yaml)
(the production-task-auth environment plus a `registry` block) and
[`bom/bom.json`](../../../bom/bom.json); CI fails if the committed files differ
from a fresh generation. [Registry mirroring](../../../docs/registry-mirroring.md)
explains the `registry` block, how to copy the artifacts and how to check the
copy.

The mirror hosts are placeholders under `example.test`:

| Class | Mirror in this example | For example |
|---|---|---|
| product charts and images | `registry.example.test/steward-platform`, upstream registry dropped | `ghcr.io/apelogic-ai/charts/steward` becomes `registry.example.test/steward-platform/apelogic-ai/charts/steward` |
| dependency charts and images | `registry.example.test/steward-platform`, upstream registry kept (`keepSourceHost`) | `quay.io/jetstack/charts/cert-manager` becomes `registry.example.test/steward-platform/quay.io/jetstack/charts/cert-manager` |
| Git sources | `https://git.example.test/mirrors`, upstream host kept | `https://github.com/kubernetes-sigs/gateway-api` becomes `https://git.example.test/mirrors/github.com/kubernetes-sigs/gateway-api` |

The files are the task-auth example's, with these differences:

- every `OCIRepository` (the four charts, and the Envoy Gateway chart that the
  `envoy-gateway-crds` `Kustomization` extracts its CRDs from) points at the
  mirror, pins the BOM digest and authenticates with `secretRef`
  `registry-example-test`;
- both `GitRepository` objects (the Gateway API CRDs at the BOM commit, and
  this repository at the platform tag for `charts/steward-edge`) point at the
  Git mirror and authenticate with `secretRef` `git-example-test`;
- every image in the `HelmRelease` values is its BOM image in the mirror, at
  its BOM digest, and every workload, the Envoy proxies included, pulls with
  the image pull Secret `registry-example-test`.

## What the operator supplies

Everything the [task-auth example](../task-auth/README.md#what-the-operator-supplies)
lists, and:

- the artifacts, copied into the mirror
  ([copy procedure](../../../docs/registry-mirroring.md#copy-the-artifacts)),
  and checked with `scripts/verify-digests.sh --mirror`;
- in `flux-system`: a `kubernetes.io/dockerconfigjson` Secret
  `registry-example-test` for the registry, and a Secret `git-example-test`
  with the Git mirror's credentials (or no `flux.secretRef`, and a
  `flux.provider` such as `aws`, for a cloud registry the source controller
  reaches with its workload identity);
- a `kubernetes.io/dockerconfigjson` Secret `registry-example-test` in each
  namespace a chart installs into: `steward`, `cert-manager`, `identity` and
  `envoy-gateway-system`.

Secrets are referenced by name, never generated.

## Use it

```sh
cp -r environments/production-mirrored environments/<name>   # then edit it
scripts/mirror-list.sh --installed --mirrored environments/<name>/platform-values.yaml > mirror-list.json
# copy each artifact (docs/registry-mirroring.md), then check the mirror:
scripts/verify-digests.sh --mirror environments/<name>/platform-values.yaml --installed
scripts/generate.sh environments/<name>/platform-values.yaml
# copy generated/<name>/flux/ into the Git path your Flux Kustomization watches
```

## What CI checks

[`tests/flux/run.sh`](../../../tests/flux/run.sh) runs every check of the
other examples here, with each expected reference rewritten to the mirror,
and also that every `OCIRepository` and `GitRepository` points at the mirror
with its class's credentials, and that every workload image the charts render
is a BOM image from the mirror at its BOM digest.
[`tests/generate/run.sh`](../../../tests/generate/run.sh) checks the same
environment's helmfile inputs: charts from the mirror at their BOM digests,
the CRD manifests downloaded from the manifests mirror, registry logins, and
the image pull Secrets on every workload. The
[core end-to-end test](../../../tests/e2e/core/README.md) installs the core
profile from a real (local) mirror in CI.

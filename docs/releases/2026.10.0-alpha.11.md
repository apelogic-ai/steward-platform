# Steward platform 2026.10.0-alpha.11

A pre-release of the Steward platform BOM that moves two products to their
current releases:
- **Steward 0.3.11:** Task library and Task pages, governed GitHub repository
  automation, the two-file repository package path, the seven-step Get started
  journey, and a configurable starter task.
- **steward-run 0.8.1:** the `package-path` invocation that Steward's two-file
  path uses.

github-oidc-exchange 0.7.5 and mcp-gw 0.5.7 are unchanged. The platform itself
(generator, helmfile, Flux output, scripts, platform values schema) is unchanged
from [2026.10.0-alpha.10](2026.10.0-alpha.10.md). It is an alpha: the governed
profile, which runs agents, is not in it yet.

**No breaking changes for the core, task-auth and browser-admin profiles.**
- **Platform values:** values written for alpha.10 validate unchanged and
  generate the same install with the new product coordinates.
- **Migrations:** Steward 0.3.11 adds migrations 0064 to 0067, so rolling back
  to 0.3.8 needs a database restore.
- **Steward's projected `stewardRunRelease`** now names steward-run 0.8.1, so
  Steward-generated callers switch to the two-file `package-path` form.
  Existing `invocation-path` callers keep working.

[`bom/bom.json`](../../bom/bom.json) at this version is authoritative. The
tables below abbreviate digests to 12 hex characters for reading; install from
the full digests in the BOM, never from tags.

### What changed in each product

#### Steward 0.3.11

[Release notes](https://github.com/apelogic-ai/steward/releases/tag/v0.3.11),
[changelog](https://github.com/apelogic-ai/steward/blob/v0.3.11/CHANGELOG.md).
0.3.9 and 0.3.10 must not be used:
- **0.3.9:** published artifacts, then failed clean-cluster acceptance because
  the chart schema required the new starter-task value.
- **0.3.10:** failed repository validation before publishing anything.

0.3.11 contains all of their changes. From 0.3.8, the changes are:

- **Two-file repository packages.** A same-repository direct Task can be
  submitted by `packagePath`, without a separate invocation manifest. A Task
  definition can carry its prompt inline as `promptText`. Steward advertises
  `steward_package_path_supported` in its protected-resource metadata.
- **Task pages and a Task library.** Each Task gets a page addressed by its exact
  package digest: files, metadata, runs and repeat execution. A Task library
  adds owner-scoped drafts, immutable content-addressed versions and role
  sharing.
- **Governed GitHub repository automation.** These steps run through the
  user's own governed GitHub connection (new internal authority v4):
  - repository discovery and readiness;
  - publishing the exact tested package and its pinned caller workflow as a
    pull request;
  - workflow detection, dispatch and run status.
- **Get started 2.0** is the seven-step journey from a governed browser test to
  a governed GitHub Actions run. Progress comes from persisted server evidence.
- **A configurable starter task** (`config.apiserver.starterTask`), validated at
  startup and served at runtime, with a corrected built-in Hello World prompt.
- **Execution logs separate from outputs.** New output archives contain only
  `out/`, and stdout and stderr stay in the execution-log endpoints.
  Run-event history is bounded.
- **Additive migrations 0064 to 0067.**

The generated Steward values change only in image tags and digests. The new
chart values are optional. The provider-profile bundle stays at
`steward-runtime-providers@1.2.2`.

#### steward-run 0.8.1

[Release](https://github.com/apelogic-ai/steward-run/releases/tag/v0.8.1),
[changelog](https://github.com/apelogic-ai/steward-run/blob/v0.8.1/CHANGELOG.md).
0.8.0 must not be used: its release stopped before publishing anything, and
0.8.1 carries its changes unchanged. From 0.7.6, the changes are:

- **`package-path` and `execution-log` inputs** on the action and every reusable
  workflow, mutually exclusive with `invocation-path`. They are gated on
  Steward's `steward_package_path_supported` capability before the token
  exchange.
- **A refreshed signed governed job-container image** and a pre-tag release
  preflight that checks its version labels and signature.

#### github-oidc-exchange 0.7.5 and mcp-gw 0.5.7

Unchanged from alpha.10.

## Upgrading from 2026.10.0-alpha.10

- **Platform values** from alpha.10 validate unchanged. Regenerating with this
  BOM changes only product coordinates:
  - the Steward chart digest and image tags and digests;
  - the projected `stewardRunRelease` (version, workflow and action commit,
    job-container image);
  - the steward-run chart and runner image;
  - the `platformVersion` and `GitRepository` tags.
- **Back up the Steward database first.** The apiserver and controller apply
  migrations 0064 to 0067 on startup. Rolling back to 0.3.8 means restoring that
  backup with the 0.3.8 chart and image set.
- **Apply** with `helmfile --environment <env> --kube-context <context> sync`,
  or let Flux reconcile the regenerated objects. Deploy the Steward chart and
  images as one release unit. Browser sessions are signed out once.
- **Callers:** Steward now generates two-file `package-path` callers.
  - Existing callers that use `invocation-path` keep working unchanged.
  - Callers saved under the old shared `.github/workflows/steward-browser-task.yml`
    keep running, but Get started detects and dispatches only the per-Task
    caller it publishes. Republish the Task to adopt it.
- **Steward governed users** (outside this BOM): no provider-profile transition.
  The SPIRE settings from the alpha.10 notes still apply.
- **Registry mirror and built mode:** copy or rebuild the new Steward and
  steward-run artifacts. An alpha.10 lock is refused.
- **Rolling back** to alpha.10 means generating from an alpha.10 checkout and
  restoring the pre-upgrade Steward database.

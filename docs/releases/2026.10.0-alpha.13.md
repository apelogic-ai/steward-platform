# Steward platform 2026.10.0-alpha.13

A pre-release of the Steward platform BOM that moves Steward to its current
release:
- **Steward 0.3.15** (with the changes of 0.3.14): the Connections bridge
  speaks MCP Streamable HTTP sessions, so governed GitHub operations work
  behind the mcp-gw agentgateway pinned in this BOM; governed Git and scratch
  Task workspaces; opt-in managed inference credentials, with stock inference
  still the default; and additive migration 0068.

steward-run 0.8.1, github-oidc-exchange 0.7.5 and mcp-gw 0.5.7 are unchanged.
The platform itself (generator, helmfile, Flux output, scripts, platform values
schema) is unchanged from [2026.10.0-alpha.12](2026.10.0-alpha.12.md). It is an
alpha: the governed profile, which runs agents, is not in it yet.

**No breaking changes for the core, task-auth and browser-admin profiles.**
- **Platform values:** values written for alpha.12 validate unchanged and
  generate the same install with the new product coordinates.
- **Migrations:** one, the additive 0068 (managed inference credentials). It
  runs on upgrade in every profile and stays in place on rollback. These
  profiles admit no Task, so rolling back to alpha.12 needs no database
  restore (see [Upgrading](#upgrading-from-2026100-alpha12)).
- **Helm values:** Steward 0.3.15 adds the `inference` and `workspace` values
  and two managed-inference Secret references. Their defaults (stock
  inference, both workspace types with the chart's ceilings) apply unchanged;
  the platform generator sets none of them. 0.3.14 adds no chart values.

[`bom/bom.json`](../../bom/bom.json) at this version is authoritative. The
tables below abbreviate digests to 12 hex characters for reading; install from
the full digests in the BOM, never from tags.

### What changed in Steward

Release notes:
[0.3.14](https://github.com/apelogic-ai/steward/releases/tag/v0.3.14),
[0.3.15](https://github.com/apelogic-ai/steward/releases/tag/v0.3.15);
[changelog](https://github.com/apelogic-ai/steward/blob/v0.3.15/CHANGELOG.md).
0.3.14 was released but never pinned in a BOM. It is not skipped: 0.3.15
contains all of its changes, and this BOM ships them. From 0.3.13, the changes
are:

- **MCP Streamable HTTP sessions in the bridge (0.3.14).** The Connections
  bridge now opens an MCP session before its tool calls: `initialize`, then
  `notifications/initialized`, then each tool call with the issued
  `Mcp-Session-Id` and the negotiated `MCP-Protocol-Version`, and a
  best-effort session `DELETE` at the end. It re-initializes once when the
  gateway answers `404` for an ended session. On 0.3.13 and earlier, a
  deployment whose `connectionsBridge.mcpGatewayOrigin` is a session-enforcing
  gateway, such as the mcp-gw 0.5.7 agentgateway this BOM pins, could not
  publish a task definition, detect or dispatch its workflow, read run status,
  rerun, or search repositories with an explicit query: each failed with
  `bridge-gateway-http` and upstream status `400`. A direct GitHub wrapper
  origin, which issues no session, keeps working without a session header. A
  new failure category, `bridge-gateway-session` (`gateway_session_failed` at
  the Connections API), reports a session the gateway rejected or that could
  not be established; every other failure keeps its category. The session
  `DELETE` is permitted by provider-profile bundle 1.2.2.
- **Governed Git and scratch workspaces (0.3.15).** TaskDefinition v2 can
  request exact, admitted Git commits (bounded history, paths and admitted
  submodules) and bounded scratch space. Steward resolves and authorizes every
  entry before the runtime is created, materializes it under
  `/sandbox/workspace` without repository credentials or remotes, and records
  immutable workspace evidence. Git sources come only from the
  `githubSource.bindings` catalog. The chart's new `workspace` values set the
  deployment ceilings, which each User Envelope's `workspace` ceiling and the
  Task bound again; an Envelope without that ceiling grants no workspace. The
  Task editor, Run now and Get started can configure a repository checkout,
  and Run details show the resolved entries. Tasks without `workspace` behave
  as before.
- **Managed inference, opt-in (0.3.15).** With `inference.mode: managed`, Mint
  resolves each user's own encrypted inference credential through a dedicated
  least-privilege PostgreSQL reader, and users manage that credential under
  `/app/api/v1/connections/inference`. Managed mode needs the
  `secrets.managedInferenceDatabase` reader credential, the
  `secrets.managedInferenceEncryptionKey` Secret and, with NetworkPolicy,
  PostgreSQL egress for Mint. **Stock mode stays the default** and projects
  none of this material. Switching modes means stopping submissions and
  draining or revoking existing runtimes first; live runtimes are never
  switched in place. 0.3.14 added only an unwired Mint library component for
  this, with no behavior change.
- **Migration 0068 (0.3.15).** `0068_managed_inference_credentials.sql` adds
  the encrypted per-user credential table and its append-only audit history.
  It is additive, runs on upgrade whatever the inference mode, and is
  intentionally left in place on rollback.
- **Rollback needs a database restore once workspace evidence exists
  (0.3.15).** Releases before 0.3.15 cannot read the new evidence shape or the
  framed workspace input. After any Task with workspace evidence has been
  stored, rolling back to 0.3.14 or earlier requires restoring a database
  backup taken before that Task.
- **agentgateway end-to-end coverage (0.3.15).** Steward's governed-connections
  end-to-end test now deploys the mcp-gw 0.5.7 agentgateway this BOM pins,
  proves that it requires a session, and runs repository search, publication,
  workflow detection and dispatch through it. The direct-wrapper case stays
  covered. This is Steward's release test; the platform's own end-to-end tests
  do not install mcp-gw yet.
- **New images.** Every Steward image is a new build at 0.3.15, the `bridge`
  image (`sha256:95374a6f9901`) included. The core, task-auth and
  browser-admin profiles do not enable the Connections bridge; governed
  installs outside this BOM must move `connectionsBridge.image`,
  `sourceCommit`, `signerIdentity` and `attestationBundle` to the 0.3.15
  release's stable bridge provenance inputs, because an earlier bridge keeps
  the session defect.

The generated Steward values change only in image tags and digests. The
rendered apiserver and controller now carry the chart's default inference mode
(`stock`), and the apiserver the default workspace policy. The provider-profile
bundle identity stays `steward-runtime-providers@1.2.2`.

## Upgrading from 2026.10.0-alpha.12

- **Platform values** from alpha.12 validate unchanged. Regenerating with this
  BOM changes only the Steward chart digest, the Steward image tags and
  digests, and the `platformVersion` and `GitRepository` tags.
- **Back up the Steward database** before upgrading. Migration 0068 runs when
  the new apiserver and controller start. It is additive and stays in place if
  you roll back.
- **Apply** with `helmfile --environment <env> --kube-context <context> sync`,
  or let Flux reconcile the regenerated objects. Deploy the Steward chart and
  images as one release unit.
- **Inference and workspaces:** nothing to configure. The core, task-auth and
  browser-admin profiles keep the stock inference default and do not run
  agents, so the `workspace` ceilings and the managed-inference Secrets do not
  apply to them.
- **Callers:** none change.
- **Steward governed users** (outside this BOM): update the
  `connectionsBridge` coordinates with the chart and images; keep
  `workspace.scratchVolumeSize` equal to OpenShell's workspace storage size;
  apply migration 0068 before enabling managed inference, and follow Steward's
  [managed inference](https://github.com/apelogic-ai/steward/blob/v0.3.15/docs/installation/managed-inference.md)
  procedure to switch. The SPIRE settings from the alpha.10 notes still apply.
- **Registry mirror and built mode:** copy or rebuild the new Steward
  artifacts. An alpha.12 lock is refused.
- **Rolling back** to alpha.12 means generating from an alpha.12 checkout and
  applying the 0.3.13 chart and full image set together, bridge included.
  Migration 0068 stays. The profiles in this BOM run Steward in core mode,
  which admits no Task and so stores no workspace evidence: they roll back
  without a database restore. An installation that has stored a Task with
  workspace evidence must restore a database backup from before that Task.

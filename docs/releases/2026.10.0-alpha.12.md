# Steward platform 2026.10.0-alpha.12

A pre-release of the Steward platform BOM that moves Steward to its current
release:
- **Steward 0.3.13** (with the changes of 0.3.12): fixed governed GitHub
  repository listing, a default repository picker that lists the admitted
  source repositories through the source GitHub App, one shared repository
  listing in the browser, the `execution-log: full` transcript that
  steward-run 0.8.1 requires, and latency reporting for governed connection
  operations.

steward-run 0.8.1, github-oidc-exchange 0.7.5 and mcp-gw 0.5.7 are unchanged.
The platform itself (generator, helmfile, Flux output, scripts, platform values
schema) is unchanged from [2026.10.0-alpha.11](2026.10.0-alpha.11.md). It is an
alpha: the governed profile, which runs agents, is not in it yet.

**No breaking changes for the core, task-auth and browser-admin profiles.**
- **Platform values:** values written for alpha.11 validate unchanged and
  generate the same install with the new product coordinates.
- **Migrations:** none since Steward 0.3.11; the newest is still 0067. Rolling
  back to 0.3.11 needs no database restore.
- **Helm values:** Steward 0.3.12 and 0.3.13 add no chart values and change no
  defaults or provider-profile contracts.

[`bom/bom.json`](../../bom/bom.json) at this version is authoritative. The
tables below abbreviate digests to 12 hex characters for reading; install from
the full digests in the BOM, never from tags.

### What changed in Steward

[Release notes](https://github.com/apelogic-ai/steward/releases/tag/v0.3.13),
[changelog](https://github.com/apelogic-ai/steward/blob/v0.3.13/CHANGELOG.md).
0.3.12 was released but never pinned in a BOM; 0.3.13 contains all of its
changes. From 0.3.11, the changes are:

- **Repository listing fixes (0.3.12).** Governed GitHub repository listing,
  run status and workflow dispatch match the replies of the pinned GitHub MCP
  server (v1.6.0). A blank repository query, which earlier bridges rejected,
  now has a defined meaning. Repository loading in Get started and on the Runs
  page no longer blocks the rest of the page, and a failed listing shows its
  reason with a **Retry repositories** action. New failure categories
  (`bridge-contract`, `bridge_result_too_large`) and GitHub automation `503`
  reasons separate request-contract, provider-contract and size-bound
  failures; bridge results and MCP tool replies are bounded.
- **Admitted-source repository picker (0.3.13).** With `githubSource` enabled
  and at least one binding, the browser's default repository list (a blank
  query) shows the deployment's admitted source repositories, resolved through
  the **source GitHub App** with repository-scoped, metadata-only tokens and an
  in-process stale-while-revalidate cache. Organization-owned admitted
  repositories now appear by default. **The source GitHub App installation
  must include each admitted repository**; a repository it cannot resolve is
  left out and counted in the `x-steward-unresolved-repositories` header. The
  App needs no new permission. An explicit search query still uses the
  governed per-user connection. A successful default listing is not proof of a
  GitHub connection: publication and dispatch can still fail on the user's
  connection.
- **A shared repository listing (0.3.13).** Get started step 4 now shows the
  repository picker, and Get started and the task page's publication panel
  share one listing per page load. It is fetched again only on **Refresh
  repositories**, **Retry repositories**, a page reload, or after a failure or
  a GitHub disconnect. A newly admitted repository shows as **Ready** only
  after a refresh or reload.
- **The `execution-log: full` transcript fix (0.3.13).** Steward 0.3.11 and
  0.3.12 left the reserved stdout and stderr transcript out of the runner
  output archive, so steward-run 0.8.1 callers that set
  `execution-log: full`, including the callers Steward generates, reported
  `failure-category=input-output` after the Task had succeeded. 0.3.13 adds
  the transcript back for `full` Tasks. A `full` Task whose transcript or
  stored archive is invalid gets a non-retryable `task_output_delivery_failed`
  error. No caller change is needed.
- **Latency reporting (0.3.13).** Governed connection-operation reconciliation
  logs one structured line per completed attempt with queue wait, attempt
  duration and total latency. No metrics surface or cadence changed.
- **No migrations** since 0.3.11; the newest migration is still 0067.
- **The bridge image moved.** The `bridge` image is a new build at 0.3.13
  (`sha256:63706e017145`), and an earlier bridge rejects the blank repository
  query that the 0.3.12 and later apiserver sends. The core, task-auth and
  browser-admin profiles do not enable the Connections bridge; governed
  installs outside this BOM must move `connectionsBridge.image`, `sourceCommit`,
  `signerIdentity` and `attestationBundle` to the 0.3.13 release's stable
  bridge provenance inputs.

The generated Steward values change only in image tags and digests. The
provider-profile bundle identity stays `steward-runtime-providers@1.2.2`.

## Upgrading from 2026.10.0-alpha.11

- **Platform values** from alpha.11 validate unchanged. Regenerating with this
  BOM changes only the Steward chart digest, the Steward image tags and
  digests, and the `platformVersion` and `GitRepository` tags.
- **No migrations** run. Back up the Steward database as usual before any
  upgrade; rolling back to alpha.11 needs no restore.
- **Apply** with `helmfile --environment <env> --kube-context <context> sync`,
  or let Flux reconcile the regenerated objects. Deploy the Steward chart and
  images as one release unit.
- **Source GitHub App:** where `githubSource` has bindings, make sure the App
  installation includes every admitted source repository, or that repository
  is missing from the default picker.
- **Callers:** none change. Callers that dropped `execution-log: full` to work
  around the missing transcript can request it again once their Steward runs
  0.3.13.
- **Steward governed users** (outside this BOM): update the
  `connectionsBridge` coordinates with the chart and images. The SPIRE settings
  from the alpha.10 notes still apply.
- **Registry mirror and built mode:** copy or rebuild the new Steward
  artifacts. An alpha.11 lock is refused.
- **Rolling back** to alpha.11 means generating from an alpha.11 checkout and
  applying the 0.3.11 chart and full image set together, bridge included.
